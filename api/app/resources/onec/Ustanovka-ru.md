# Установка интеграции Innova PBX ↔ 1С (на русском)

Это руководство охватывает обе стороны: настройку **в панели Innova PBX** и
создание объектов **в конфигурации 1С**. Файлы: `InnovaPBX_HTTPServis.bsl`,
`InnovaPBX_Ulanish.bsl`, `Metadata-tavsifi.md` (в этой же папке).

> Важно: этот BSL-код подготовлен на сервере без установленной платформы
> 1С:Предприятие — проверен ТОЛЬКО синтаксически. Перед продуктивным
> использованием обязательно протестируйте в тестовой (копии) базе.

## Шаг 1 — Создание API-ключа в панели Innova PBX

1. Войдите в панель под учётной записью администратора → раздел
   **Интеграции**.
2. В карточке **REST API** → **Настроить** → **Создать ключ**.
3. Имя: например `1C-Бухгалтерия`. Выберите только нужные scope:
   - `calls:read` — если нужна история звонков.
   - `recordings:read` — если нужно скачивать записи разговоров из 1С.
   - `calls:originate` — если нужен клик-ту-колл из 1С.
   - `extensions:read` — если нужен список внутренних номеров.
4. После создания ключ (`ipk_...`) показывается **ТОЛЬКО ОДИН РАЗ** —
   скопируйте и сохраните его в надёжном месте (менеджер паролей). Повторно
   посмотреть ключ НЕВОЗМОЖНО, только отозвать и создать новый.

## Шаг 2 — Создание Webhook (события PBX → 1С)

1. **Интеграции** → **Webhook'и** → **Создать**.
2. **URL**: адрес HTTP-сервиса 1С, например:
   `https://1c.example.ru/innova-pbx/hs/innova/event`
   (см. `Metadata-tavsifi.md`, раздел 1; публикация — шаг 3 ниже).
3. **События**: отметьте нужные (`call.ringing`, `call.answered`,
   `call.ended`; при необходимости включите `include_internal`).
4. После создания **secret** (например `whsec_...`) показывается **ТОЛЬКО
   ОДИН РАЗ** — скопируйте и сохраните. Это значение понадобится в 1С
   (шаг 3, пункт 3).

## Шаг 3 — Создание объектов в конфигурации 1С

Откройте Конфигуратор и создайте объекты согласно `Metadata-tavsifi.md`:

1. **HTTP-сервис** `InnovaPBX` (шаблон `innova`, метод `/event` → POST →
   модуль `InnovaPBX_HTTPServis`, функция `ОбработкаСобытия`). Текст модуля
   скопируйте из `InnovaPBX_HTTPServis.bsl`.
2. **Общий модуль** `InnovaPBX_Ulanish` (На сервере = Истина). Текст модуля —
   из `InnovaPBX_Ulanish.bsl`.
3. **Константы**: `PBXАдресСервераAPI` (значение — адрес панели PBX,
   например `https://pbx.example.ru`), `PBXТаймаутHTTPС` (по умолчанию `30`),
   `PBXДопустимоеОтклонениеВременнойМеткиС` (по умолчанию `300`).
4. **Регистры сведений** `PBXВходящиеДоставки` и `PBXСобытияЗвонков`
   (структура — пункты 3–4 файла `Metadata-tavsifi.md`).
5. Хранение секретов:
   - Если установлена БСП (Библиотека стандартных подсистем) — выполните
     один раз (через обработку или консоль):
     `БезопасноеХранилищеДанных.УстановитьЗначение("InnovaPBX_WebhookSecret", "whsec_...")`
     и `..."InnovaPBX_APIКлюч", "ipk_..."`.
   - Если БСП нет — создайте регистр `PBXСекреты` (пункт 5) и внесите две
     записи: `Ключ="WebhookSecret"`, `Значение="whsec_..."` и
     `Ключ="APIКлюч"`, `Значение="ipk_..."`.
6. Обновите конфигурацию и примените изменения к базе.

## Шаг 4 — Публикация (Apache/IIS)

HTTP-сервисы 1С работают через веб-сервер (для приёма внешних запросов от
PBX публикация обязательна):

1. В Конфигураторе: **Администрирование → Публикация на веб-сервере**.
2. Имя: например `innova-pbx`. Каталог — рабочий каталог веб-сервера.
3. Включите флаг **HTTP-сервисы** (без него webhook не будет работать).
4. **Опубликовать** — будут созданы файлы публикации (`default.vrd` и
   модуль/конфигурация веб-сервера, в зависимости от платформы).
5. Настройте HTTPS-сертификат (PBX ожидает `https://`; §3 контракта проверяет
   только схему http/https и запрещённые адреса, но TLS настоятельно
   рекомендуется).
6. Проверка: запрос **GET** в браузере на
   `https://1c.example.ru/innova-pbx/hs/innova/event` должен вернуть 405
   (Method Not Allowed), так как зарегистрирован только POST — это означает,
   что публикация работает.

## Шаг 5 — Проверка (тест)

1. В панели Innova PBX в таблице **Webhook'и** нажмите **Тест** у созданной
   записи — отправится событие `test.ping`.
2. В **журнале доставок** (Deliveries) статус должен быть `2xx`.
3. В 1С: проверьте, что в `РегистрСведений.PBXВходящиеДоставки` появилась
   новая запись (через Конфигуратор или консоль запросов).
4. Если возвращается `401 invalid_signature` — проверьте, что secret в 1С и в
   панели PBX совпадает побайтово (без пробелов и лишних символов).
5. Если возвращается `401 stale_timestamp` — проверьте синхронизацию времени
   (NTP) между сервером 1С и сервером PBX (окно ±300 секунд).

## Шаг 6 — Исходящий звонок (опционально, нужен scope `calls:originate`)

Для проверки из 1С напишите короткую обработку (или выполните в консоли):

```bsl
Результат = InnovaPBX_Ulanish.ВызватьИзPBX("+79991234567", "101");
Если Результат.Успех Тогда
	Сообщение = "Запрос отправлен: " + Результат.ИдентификаторЗапроса;
Иначе
	Сообщение = "Ошибка (" + Результат.КодОшибки + "): " + Результат.Сообщение;
КонецЕсли;
```

В результате внутренний номер `101` должен зазвонить, а после ответа —
должен быть набран номер `+79991234567`.

## Устранение неполадок

| Признак | Причина | Решение |
|---|---|---|
| `401 invalid_api_key` | Ключ неверен/отозван | Создайте новый ключ в панели, обновите настройку в 1С |
| `403 insufficient_scope` | У ключа нет нужного scope | Добавить scope к ключу НЕЛЬЗЯ — создайте новый ключ с нужными правами |
| `422` при originate | Неверный формат `to` или номер занят/не существует | Проверьте формат номера (`normalize_number`) и статус внутреннего номера |
| `429` | Превышен лимит 120/мин | Снизьте частоту запросов или добавьте задержку и повтор |
| Webhook не приходит | Не включены HTTP-сервисы в публикации или блокировка firewall | Перепроверьте шаг 4, выполните `curl -I` с сервера PBX на адрес 1С |

> **Требование к платформе:** 1С:Предприятие 8.3.11 или новее.
