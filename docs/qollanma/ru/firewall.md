# Firewall

Внешняя защита сервера — здесь вы управляете тем, с каких адресов разрешено подключение к службам
**SSH**, **веб-панели**, **SIP** и **RTP (голос)**, а также какие адреса **полностью блокированы**.
Изменение, как и на странице **Сеть**, сначала проверяется, затем ожидает подтверждения и, если не
подтверждено в срок, **автоматически откатывается** к прежнему состоянию — это защита от полной потери
доступа к серверу.

## Где находится

Меню: **Система → Firewall**. Кто видит: только пользователь с правами `*` (полный администратор).

## Основные понятия

- **Служба** — их четыре: **SSH**, **Веб-панель**, **SIP**, **RTP (голос)**. У каждой свой независимый
  режим.
- **Режим**: **Открыто для всех** (без ограничений) или **Только из списка** (allowlist) — подключиться
  можно только с указанных IPv4-адресов CIDR.
- **Разрешённые CIDR** — список адресов, вводимых в режиме allowlist (например `192.168.1.0/24`); если
  оставить пустым, никто не сможет подключиться (нужен хотя бы один CIDR).
- **Блокированные адреса** — с адресов из этого списка закрываются **ВСЕ** порты (независимо от службы) —
  самое строгое ограничение.
- **Защита от самоблокировки** — система не принимает настройку, которая **сама автоматически
  заблокирует** адрес/сессию, с которой вы подключены — в этом случае показывается предупреждение и
  изменение не применяется.
- **Черновик (draft)** — изменения на экране не отправляются на сервер сразу, внизу показывается, сколько
  изменений накоплено.
- **Поток Применение → Подтверждение** — как на странице **Сеть**: **Применить** проверяет данные,
  показывает **что изменится (diff)**, вы указываете **время на подтверждение** (по умолчанию **120
  секунд**) и подтверждаете. Изменение вступает в силу сразу, но остаётся в состоянии **ожидания**.
- **Автоматический откат** — если не нажать **Подтвердить** в указанный срок, изменение
  **автоматически откатывается** к прежнему состоянию; в любой момент можно откатить вручную кнопкой
  **Откатить сейчас**.

## Поля

| Поле | Что делает | Пример / по умолчанию |
|---|---|---|
| **Служба** → Режим | Открыто для всех / Только из списка | По умолчанию зависит от службы |
| Разрешённые CIDR | Разрешённые адреса в режиме allowlist | `192.168.1.0/24` |
| Блокированные адреса | Адреса, у которых закрываются все порты | — |
| Время на подтверждение (секунды) | Срок подтверждения после применения | 120 секунд |

## Как это делается

### Изменение режима службы
1. В разделе **Службы** в строке нужной службы (SSH/Веб-панель/SIP/RTP) выберите режим.
2. При выборе **Только из списка** введите адреса в поле **Разрешённые CIDR** (через запятую или с новой
   строки).

### Блокировка адреса
1. В поле **Блокированные адреса** введите нужные IPv4 CIDR (через запятую или с новой строки).

### Применение и подтверждение изменений
1. Если в черновике есть изменения, нажмите **Применить** на нижней панели.
2. Система проверяет данные; при ошибке соответствующие поля выделяются красным.
3. Если всё верно, показывается **что изменится (diff)** — укажите **время на подтверждение** (по
   умолчанию 120 секунд) и подтвердите **Применение**.
4. Изменение сразу вступает в силу и переходит в состояние **ожидания** — сверху отображается
   обратный отсчёт в реальном времени.
5. Убедившись, что доступ к серверу (SSH/веб-панель) по новым правилам работает, нажмите
   **Подтвердить**.
6. Если не успеете подтвердить в срок, система **автоматически откатит** состояние; для немедленного
   откатывания можно нажать **Откатить сейчас**.

### Отмена черновика
1. Ещё не применённые изменения можно отбросить кнопкой **Отменить**.

## Советы и ограничения

> [!WARNING]
> Если новыми правилами вы потеряете доступ к серверу (особенно SSH/веб-панель) — **не беспокойтесь**:
> если вы не подтвердили изменение, по истечении указанного срока система **сама** вернёт прежнее
> состояние.

> [!TIP]
> Перед ограничением SSH и веб-панели режимом **Только из списка** обязательно добавьте в список
> собственный адрес(а) подключения — иначе настройка не будет принята (защита от самоблокировки).

- Список блокированных адресов имеет приоритет над режимом службы — указанный там адрес не сможет
  подключиться к любой службе.
- Одновременно может быть только одно изменение в состоянии **ожидания** — пока оно не разрешено
  (подтверждено/откатано), новое применить нельзя.
- В режиме allowlist нельзя оставить пустой список — нужен хотя бы один CIDR.

## Проблемы и решения

| Признак | Причина | Решение |
|---|---|---|
| «Внимание: эта настройка могла заблокировать текущего администратора» | Ваш адрес попадает в allowlist/блокировку | Добавьте свой адрес в allowlist или удалите его из блокированных |
| «Никого нет — в режиме allowlist нужен хотя бы один CIDR» | Выбран режим allowlist, но список пуст | Введите хотя бы один CIDR |
| «Проверка не пройдена» | Неверный формат CIDR или пустое обязательное поле | Исправьте поля, выделенные красным |
| Изменение осталось в состоянии ожидания | Не подтверждено/не откатано | Нажмите **Подтвердить** или **Откатить сейчас**, либо дождитесь истечения срока |
| После применения нет доступа к серверу (SSH/веб) | Введён неверный CIDR | Ничего не делайте — по истечении срока произойдёт автоматический откат |
| «Настройки Firewall доступны только для просмотра» | Блокировка по причине `readonly_reason` | Устраните указанную причину и попробуйте снова |
