# Аналитика

Общая картина по call-центру и общему потоку звонков: сколько было звонков, сколько получили ответ, какое
среднее время ожидания, какой уровень SLA. Для руководителя — все цифры на одном экране вместо
ежедневного отчёта.

## Где находится
Меню: **Отчёты → Аналитика**. Кто видит: пользователь с правом `reports:view` или `reports:edit`.

## Основные понятия

- **Уровень SLA** — процент звонков, на которые ответили в течение установленного времени (основан на
  пороге SLA в настройках очереди, [Очереди](/docs/queues)).
- **Пропущенные** — звонки, оставшиеся без ответа или прерванные по истечении времени ожидания в очереди.
- Диаграммы и таблицы обновляются в соответствии с выбранным **периодом** и **фильтром по очереди**.

## Поля

| Поле | Что делает | Пример / по умолчанию |
|---|---|---|
| Период | Сегодня / Вчера / Последние 7 дней / Последние 30 дней / Другой (диапазон дат) | По умолчанию: последние 7 дней |
| Начало / Конец | Отображается только при выборе «Другой» — диапазон дат | Максимум — 92 дня |
| Очередь | Фильтрация только по одной очереди | По умолчанию: все очереди |

## Как это делается

### Просмотр по периоду и очереди
1. Выберите **Период** (быстрый вариант или введите свой диапазон дат через **Другой**).
2. При необходимости выберите одну очередь из списка **Очередь** — все KPI, диаграммы и таблицы сузятся
   до значений этой очереди.
3. Карточки KPI (всего звонков, с ответом, пропущенных, среднее время ожидания, средняя длительность
   разговора, уровень SLA) рассчитываются автоматически.

### Как читать диаграммы
1. Диаграмма **По дням** — число звонков с ответом/пропущенных за каждый день.
2. Диаграмма **По часам** — распределение входящих/отвеченных/пропущенных звонков по часам суток — удобно
   для определения самых загруженных часов.

### Анализ таблиц по очередям и операторам
1. В таблице **По очередям** сравните для каждой очереди показатели звонков, ответов, пропущенных,
   среднего времени ожидания и SLA.
2. В таблице **По операторам** посмотрите число отвеченных звонков каждого оператора, общее время
   разговоров и среднюю длительность разговора.

## Советы и ограничения

> [!TIP]
> Если используется несколько очередей, сначала посмотрите общую картину с **Все очереди**, затем
> проверьте каждую очередь отдельно — так быстрее найдёте проблемную очередь.

- Диапазон дат должен быть не более **92 дней** — при выборе более длинного диапазона появится сообщение
  об ошибке.

## Проблемы и решения

| Признак | Причина | Решение |
|---|---|---|
| Сообщение «Неверный диапазон дат» | Дата окончания раньше начала или диапазон длиннее 92 дней | Сократите диапазон дат или исправьте порядок |
| В диаграмме/таблице «Нет данных за этот период» | В выбранном периоде/очереди не было звонков | Измените период или очередь |
| Значения KPI отображаются как «—» | Данные ещё загружаются или не найдено соответствующих записей | Подождите немного; если не исчезло — обновите страницу |
