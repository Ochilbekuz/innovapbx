# Интеграции

Подключение Innova PBX к внешним системам (CRM, 1С, собственный сайт, другие программы) выполняется
здесь: ключи для открытого REST API, вебхуки, сообщающие о событиях, подключение Bitrix24/amoCRM, готовые
примеры для 1С и дополнительные настройки (публичный адрес, запись звонков, синтез речи).

## Где находится
Меню: **Система → Интеграции**, семь вкладок: **Обзор**, **API-ключи**, **Вебхуки**, **Bitrix24**,
**amoCRM**, **1С**, **Настройки**. Кто видит: раздел виден всем, но изменять может только пользователь с
правами `*` (полный администратор) — остальным показывается баннер «Только просмотр».

## Основные понятия

- **API-ключи** — ключ для доступа к открытому API `/api/public/v1/*`; у каждого свои **права (scope)**:
  чтение звонков, чтение записей, инициация вызова, чтение внутренних номеров, поток событий
  (WebSocket). Полное значение ключа при создании показывается **только один раз**.
- **Поток событий WebSocket** — ключ с правом `events:read` позволяет получать события звонков в реальном
  времени; на странице есть готовый пример подключения.
- **Вебхуки** — о событии звонка (поступил/отвечен/завершён) на ваш сервер отправляется HTTP POST; к
  каждой отправке добавляется подпись (`X-Innova-Signature`), секрет которой показывается один раз и может
  быть в любой момент **заменён**. Отправка на loopback/системные адреса запрещена.
- **Журнал доставок** — показывает каждую отправку вебхука (успешно/ошибка/остановлен) и HTTP-код;
  неуспешные/остановленные можно **отправить повторно**.
- **Bitrix24** — запись завершённых звонков в карточку CRM, создание лида для неизвестных номеров,
  попап/click-to-call. Пользователи сопоставляются **автоматически** по полю **«Внутренний номер»** в
  профиле сотрудника (**«Синхронизировать из Bitrix24»**); при желании можно поправить вручную.
  Дополнительно: сначала направлять **ответственному менеджеру**, показывать имя звонящего, загружать
  запись в карточку, периодическая авто-синхронизация пользователей.
- **amoCRM** — запись завершённых звонков в CRM, перенос неизвестных номеров в «Неразобранное»,
  попап/click-to-call. Сопоставление пользователей пока только вручную.
- В обеих интеграциях секретные поля (токен, адрес вебхука) после сохранения **маскируются**,
  заменяются только при повторном вводе.
- **Сопоставление пользователей (user map)** — CRM-пользователь, соответствующий каждому внутреннему
  номеру; определяется **автоматически** (системой) или **вручную**. Несопоставленные номера направляются
  стандартному пользователю.
- **1С** — отдельный сервер не требуется; загрузка готовых примеров на **BSL**, работающих через
  существующий API-ключ и вебхук. Этот код проверен только синтаксически, на платформе 1С не запускался.
- Вкладка **Настройки**: **публичный адрес** (на его основе формируются ссылки CRM/вебхуков), **срок
  действия ссылки на запись**, срок хранения **записи звонков** и ограничение только внешними звонками,
  **синтез речи (Yandex SpeechKit)** — провайдер, API-ключ, голоса по языкам, проверка.

## Поля

| Поле | Что делает | Пример / по умолчанию |
|---|---|---|
| **API-ключ** → Название / Права / Срок действия | Создание ключа | Пусто — бессрочно |
| **Вебхук** → Название / Адрес (URL) / События / Включая внутренние звонки | Новый вебхук | Только http/https |
| **Bitrix24** → Адрес входящего вебхука / Токен приложения / Создание лида / Время показа попапа (с) / ID пользователя по умолчанию / Показывать имя звонящего / Загрузка записи / Сначала ответственному + время звонка (5–120 с) / Авто-синхронизация пользователей | Подключение, звонки и маршрутизация | Время звонка по умолчанию: 20 с |
| **amoCRM** → Адрес портала / Долгосрочный токен / В «Неразобранное» / ID пользователя по умолчанию | Подключение | — |
| **Настройки** → Публичный адрес / Срок действия ссылки на запись (с) | Внешние ссылки | — |
| Запись звонков → Срок хранения (дней) / Только внешние звонки | Политика записи звонков | — |
| Синтез речи → Провайдер / API-ключ / Узбекский-русский-английский голоса | Yandex SpeechKit | По умолчанию: Отключено |

## Как это делается

### Создание API-ключа
1. На вкладке **API-ключи** нажмите **Создать ключ**.
2. Введите название, отметьте нужные **права** (хотя бы одно обязательно), при необходимости выберите
   срок действия.
3. Нажмите **Создать** — полное значение ключа показывается **только сейчас**, скопируйте и сохраните
   в надёжном месте.
4. Ненужный ключ можно отключить в списке кнопкой **Отозвать** — это действие **нельзя отменить**,
   интеграции, использующие этот ключ, сразу перестанут работать.

### Добавление и проверка вебхука
1. На вкладке **Вебхуки** нажмите **Добавить вебхук**.
2. Укажите название, адрес (URL) и для каких событий он будет отправляться; при необходимости включите
   и внутренние (ext↔ext) звонки.
3. Нажмите **Создать** — секрет подписи показывается один раз, сохраните его.
4. В списке кнопкой **Отправить тест** отправьте тестовое событие, результат смотрите в **Журнале
   доставок**.
5. Неуспешную доставку повторите в журнале кнопкой **Повторить**.
6. При необходимости обновите секрет подписи кнопкой **Сменить секрет** (старый перестанет работать).

### Подключение Bitrix24
1. На вкладке **Bitrix24** включите **Включить интеграцию Bitrix24**.
2. В админ-панели Bitrix24 создайте **Приложения → Вебхуки → Входящий вебхук**, отметьте хотя бы эти
   права (scope): `telephony`, `crm`, `user`/`user_basic`. Полученный адрес введите в поле **Адрес
   входящего вебхука**.
3. В разделе **Подключение** нажмите **Сохранить** — определится адрес портала (host), он появится на
   карточке статуса («Подключено: ...»).
4. В профиле каждого сотрудника **Bitrix24 → Сотрудники → профиль → «Внутренний номер»** укажите
   внутренний номер PBX.
5. На карточке статуса или в разделе **Пользователи** нажмите **Синхронизировать из Bitrix24** —
   загрузятся пользователи портала, они **автоматически** сопоставятся по внутреннему номеру;
   несопоставленные/с одинаковым номером случаи видны в отчёте синхронизации.
6. Для click-to-call укажите показанный адрес в настройках исходящего вебхука Bitrix24
   (`ONEXTERNALCALLSTART`), настройте также **Токен приложения (application_token)** — он нужен для
   подтверждения. Для облачного портала этот адрес обязательно должен быть **внешним (public)**
   (см. предупреждение ниже).
7. При необходимости в разделе **Маршрутизация** включите **Сначала направлять ответственному
   менеджеру** и укажите время звонка (5–120 секунд) — если ответственный занят/офлайн/не отвечает,
   звонок продолжится по обычному маршруту.
8. В разделе **Пользователи** включите **Авто-синхронизацию пользователей**, чтобы сопоставление
   обновлялось само каждые 10 минут.

### Подключение amoCRM
1. На вкладке **amoCRM** включите интеграцию, введите адрес портала и долгосрочный токен.
2. Если хотите, чтобы неизвестные номера попадали в «Неразобранное», включите эту опцию.
3. Нажмите **Сохранить** и **Проверить соединение**.

### Настройка сопоставления пользователей (Bitrix24/amoCRM)
1. **Bitrix24**: после хотя бы одной **синхронизации из Bitrix24** таблица переключается на выбор из
   списка пользователей Bitrix24. Если в строке выбрать другого пользователя из списка, он помечается
   как **«Вручную»** и не меняется при следующей синхронизации; выбрав «— по внутреннему номеру в
   Bitrix24 (авто) —», можно вернуть автоматическое сопоставление.
2. **amoCRM**: в таблице **Сопоставление пользователей** введите ID CRM-пользователя для каждого
   внутреннего номера и нажмите **Сохранить сопоставление** (пока только вручную).
3. В обеих интеграциях о несопоставленных внутренних номерах появится баннер — они направляются
   стандартному пользователю.

### Получение примеров для 1С
1. На вкладке **1С** прочитайте инструкцию: сначала создать API-ключ с правом `calls:originate`, затем
   добавить вебхук.
2. Нужный пример скачайте кнопкой **Скачать** и подключите в своей конфигурации 1С как HTTP-сервис.

### Общие настройки и синтез речи
1. На вкладке **Настройки** введите **публичный адрес** (на его основе формируются ссылки CRM/вебхуков)
   и укажите срок действия ссылки на запись.
2. В разделе **Запись звонков** настройте срок хранения (дней) и ограничение только внешними звонками.
3. В разделе **Синтез речи** выберите провайдера (Yandex SpeechKit), введите API-ключ, укажите код голоса
   для каждого языка, нажмите **Сохранить**, затем **Проверить** (проверка с несохранёнными изменениями
   невозможна — сначала нужно сохранить).

## Советы и ограничения

> [!WARNING]
> Секрет API-ключа и вебхука показывается **только один раз, в момент создания** — повторно увидеть его
> нельзя, можно только создать новый/заменить.

> [!TIP]
> На вкладке **Обзор** по карточкам (с индикатором статуса) можно одним взглядом увидеть, какая
> интеграция подключена — к подробностям переходите через кнопку **Настроить** на нужной вкладке.

> [!WARNING]
> Если портал Bitrix24 облачный (`*.bitrix24.*`), адрес click-to-call должен быть **внешним (public)** —
> облако не может достичь приватного/внутреннего адреса PBX. В этом случае на странице появится
> предупреждение и кнопка копирования адреса; укажите внешний адрес на вкладке **Настройки** и
> перенаправьте порт на PBX — тогда click-to-call заработает, остальные функции (лид, попап,
> синхронизация, загрузка записи) работают и без этого адреса.

- Адрес вебхука **не может указывать на loopback или системные адреса** — это заблокировано из
  соображений безопасности.
- Секретные поля Bitrix24/amoCRM (токен, адрес вебхука) после сохранения маскируются — если сохранить с
  пустым полем, старое значение **не изменится**.
- Если поле **«Внутренний номер»** в Bitrix24 неверно или пусто, сотрудник не сопоставится автоматически
  при синхронизации — выберите вручную в таблице или исправьте профиль и синхронизируйте повторно.
- Перед проверкой синтеза речи обязательно сохраните изменения — иначе проверка будет работать со старой
  (сохранённой) настройкой и может дать неверный результат.

## Проблемы и решения

| Признак | Причина | Решение |
|---|---|---|
| «Выберите хотя бы одно право» | При создании API-ключа не отмечено ни одно право | Отметьте нужное право (права) |
| «Отправка на этот адрес запрещена» | URL указывает на loopback/системный адрес | Укажите реальный внешний адрес |
| Вебхук «Отключён автоматически» | Подряд несколько неуспешных доставок | Прочитайте причину, проверьте адрес/сервер и включите снова |
| CRM «Соединение не удалось» | Неверный токен/адрес | Проверьте данные и сохраните повторно |
| Баннер «Несопоставленные номера» | Сопоставление пользователей не завершено | Сопоставьте в таблице **Сопоставление пользователей** или укажите стандартного пользователя |
| Таблица пользователей Bitrix24 пуста | Ещё не было ни одной синхронизации | Нажмите **Синхронизировать из Bitrix24** |
| В отчёте синхронизации «В Bitrix24 есть внутренний номер, в PBX нет» | В профиле сотрудника указан неверный/несуществующий внутренний номер | Исправьте **«Внутренний номер»** в Bitrix24 и синхронизируйте снова |
| В отчёте синхронизации «номер ... у нескольких пользователей» | Одному внутреннему номеру соответствуют несколько профилей сотрудников | Сделайте внутренние номера в профилях Bitrix24 уникальными |
| Предупреждение click-to-call (облако не достигает приватного адреса) | Bitrix24 облачный, адрес PBX приватный/внутренний | Укажите внешний (public) адрес на вкладке **Настройки** и перенаправьте порт на PBX |
| Кнопка «Проверить» для синтеза речи недоступна | Есть несохранённые изменения | Сначала нажмите **Сохранить** |
| «Настройки были изменены в другом месте» | Другой администратор сохранил их в это же время | Страница обновит значения — проверьте и сохраните повторно |
