# SIP и сеть

Базовые сетевые настройки SIP-сервера: внешний IP/домен, локальные сети, диапазон портов RTP, сертификат
TLS и каналы уведомлений о событиях SIP.

## Где находится

Меню: **Система → SIP и сеть**.

## Основные понятия

- **Внешний IP/домен** — адрес, который сообщается внешним устройствам/транкам при регистрации.
- **Локальные сети (CIDR)** — сети, которые считаются внутренними и не требуют NAT-обхода.
- **Диапазон RTP** — диапазон UDP-портов, используемых для передачи голоса.
- **Сертификат TLS** — сертификат для шифрованных SIP-соединений.
- **Уведомления** — каналы оповещения о событиях SIP (например, атаки, сбои регистрации).

## Как это делается

### Применение обнаруженной сети
1. Система может автоматически определить локальную сеть — нажмите **Применить обнаруженную сеть** для
   добавления её в список.

### Изменение настроек SIP/RTP
1. Укажите внешний IP или домен, диапазон портов RTP и порты SIP.
2. Сохраните — изменения применяются к новым соединениям.

### Загрузка сертификата TLS
1. Включите **TLS**, загрузите файл сертификата и приватного ключа.
2. Сохраните настройки — SIP по TLS станет доступен на указанном порту.

### Создание самоподписанного сертификата
1. Нажмите **Создать самоподписанный сертификат**.
2. Система сгенерирует сертификат автоматически — используйте его для тестирования, не для продакшена.

### Настройка каналов уведомлений
1. Перейдите в раздел уведомлений, добавьте Telegram-бота или другой канал.
2. Выберите типы событий, о которых нужно получать оповещения.

## Советы и ограничения

> [!WARNING]
> Неверно указанный внешний IP приводит к одностороннему или полному отсутствию звука у звонков через
> NAT — проверяйте значение после каждого изменения сетевой конфигурации сервера.

> [!TIP]
> Диапазон RTP должен совпадать с портами, открытыми во внешнем firewall провайдера/роутера — иначе голос
> не пройдёт, даже если SIP регистрируется успешно.

- Самоподписанный сертификат вызывает предупреждение безопасности у большинства клиентов — для продакшена
  используйте сертификат от доверенного центра.
- После изменения портов SIP/RTP может потребоваться перезапуск службы Asterisk.
- Локальные сети указываются в формате CIDR, несколько сетей — через запятую.
- Таймаут регистрации слишком малого значения увеличивает нагрузку на сервер частыми перерегистрациями.

## Проблемы и решения

| Признак | Причина | Решение |
|---|---|---|
| Односторонний звук | Неверный внешний IP | Проверьте и исправьте внешний IP/домен |
| Транк не регистрируется | Неверные порты SIP или блокировка firewall | Проверьте порты и правила firewall |
| TLS-соединение не устанавливается | Сертификат не загружен или неверен | Загрузите корректный сертификат и ключ |
| Нет звука на части звонков | RTP-диапазон не открыт во внешнем firewall | Откройте диапазон RTP на уровне провайдера/роутера |
| Уведомления не приходят | Канал не настроен или типы событий не выбраны | Проверьте настройки канала уведомлений |
| Частые обрывы регистрации | Слишком короткий таймаут регистрации | Увеличьте значение таймаута |
| Сервер недоступен извне после изменения сети | Ошибка в настройках внешнего IP/портов | Исправьте настройки и перезапустите службу |
